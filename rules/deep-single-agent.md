# DEEP 기본 실행: 단일 에이전트

새 DEEP 제작의 기본 경로는 **사용자가 현재 세션에서 선택한 에이전트가 자료를 대응시키며 TeX에 바로 집필하는 직접 제작**이다. 모델·effort를 고정하거나 자동 전환하지 않는다. 이 문서는 새 직접 제작에서 기존 역할별 분업·독립 검수·자동 보강·상태 등록 의무보다 우선한다. 이미 `run_state.json`이 있는 작업은 아래의 관리형 실행 절을 따르며, 비용 절감을 이유로 기존 검수 기록을 버리지 않는다. faithful은 `faithful-cost-path.md`를 따른다.

## 읽기와 설명 수준

- `../note_final_rules.md`의 내용 기준과 `deep-output-contract.md`의 디자인·수식·배치를 읽는다. 녹음·전사가 필요할 때만 `transcription-workflow.md`의 해당 단계를 추가한다. 관리자·역할별 지침을 연쇄적으로 읽지 않는다.
- 목표는 강의를 따라가고 복습할 수 있는 설명노트다. 모든 질문을 미리 해결하는 교과서를 만들지 않는다. 사용자는 남은 궁금증을 별도 대화에서 질문할 수 있다.
- 교수 설명·원본 문제·핵심 풀이·부호·단위·필수 조건은 유지한다. 이해를 막는 비약만 짧은 연결 문장이나 중간식으로 메운다.
- 매 페이지에 일정 문단 수나 설명 항목 수를 강제하지 않는다. 자명한 대수 변형, 주변 이론, 대안 유도, 추가 예시, 예상 질문을 자동으로 늘리지 않는다. 원자료에 있는 유도·예시는 임의 삭제하지 않는다.
- 단순한 문체 선호 때문에 보강·검수를 반복하지 않는다. 사실·수식 오류, 원자료 누락, 이해를 막는 논리 비약·필수 배경 누락, 교수 설명의 의미·조건 약화, 읽을 수 없는 출력은 수정한다. 발견한 결함과 영향 구간만 고치고 다시 확인한다.
- 간결화는 불필요한 문장·주변 설명에 적용한다. `deep-output-contract.md`의 세리프/산세리프 글꼴 구분, 독립 수식·세로 등호 정렬·식 번호를 생략하거나 압축하지 않는다. 목차는 만들지 않는다. 이를 확인하려고 별도 검수 역할이나 회차를 추가하지 않는다.

## 직접 제작: 읽기·집필·점검·출력

1. **자료 확인과 대응:** 범위·PDF·전사 짝을 확인한다. 추출은 기존 로컬 도구로 한 번 수행하고 원본 슬라이드도 본다. 내부 작업 기록 하나에 `원자료 페이지/전사 구간 | 핵심·교수 고유 설명 | 본문 위치 | 반영/통합/제외/미해결 및 이유`를 적으며 바로 집필한다. 전사 고유 내용도 모두 처리하되 매핑만을 위한 별도 모델 호출은 하지 않는다.
2. **TeX에 통합 집필:** 원본 페이지별 절 안에 교수 설명·필요한 풀이를 함께 쓴다. 수식·교수 설명·쉬운 문체·밀도 보강을 순차적인 재집필 단계로 나누지 않는다. `deep-output-contract.md`의 조판값을 처음부터 사용한다. 검증된 템플릿은 재사용하고, 새 환경·새 조판 요소에 한해 실제 원고 일부로 짧게 시험한다.
3. **자체 내용 점검 한 번:** 주요 계산은 로컬 계산으로 확인하고, 대응표와 원고 전체를 보며 누락·논리 연결·필수 배경·교수 설명의 의미·풀이·부호·단위·조건·불확실성을 한 번 점검한다. 대응표의 판정을 갱신하고 같은 작업 기록에 짧게 결과를 남긴다. `review_method=self`, `reviewer_profile=self_review`로 명시하고 독립 검수라고 부르지 않는다. 원음이 없으면 음성 미검증을 유지한다.
4. **빌드와 시각 확인:** PDF 전체를 렌더해 확인한다. 잘림·깨진 수식·교안과 설명의 분리 등 실제 결함만 국소 수정하고 영향받은 페이지를 확인한다. 배치 때문에 내용 전체를 재검수하지 않는다. 최종 TeX/PDF 식별값과 결과를 같은 작업 기록에 남기고 끝낸다.

필수 산출물은 **TeX 기준 원고 하나, PDF, 대응·검산·QA를 합친 내부 작업 기록 하나**다. 추출·렌더 파일은 도구 산출물로 보존할 수 있다. 새 직접 제작에서는 역할별 `init/start/complete` 호출, 별도 의미 매핑 JSON·coverage JSON·인계 보고서·밀도 검수표를 의무로 만들지 않는다. 대응표가 source map과 coverage의 역할을 함께 하며, 파일 수를 줄인다는 이유로 고유 내용의 대응·판정은 생략하지 않는다.

## 기존 상태 또는 사용자 요청에 따른 관리형 실행

- 이미 `run_state.json`이 있거나 사용자가 관리형 실행을 요청하면 기존 `manage_run.py`·source map·coverage JSON·해시 계약을 그대로 사용한다. 자동 검증이 실패한 작업을 직접 제작으로 바꾸어 통과시키지 않는다.
- 새 관리형 실행의 `init`은 `multi_agent`만 만든다. 새 DEEP 단일 실행은 위 직접 제작 경로를 사용한다.
- 이미 기록된 DEEP `single_agent` 상태의 `final_reviewer`는 자체 점검이다. 변경된 기준 원고는 기존 `--patched` 등 정식 경로로 등록하며 `verify --check-inputs`를 수행한다. 상태 JSON이나 검수 원장을 직접 고치지 않는다. `set-mode faithful`은 독립 검수 경로로 전환하고 기존 집필 이후 통과를 무효화한다.
- 분업·독립 검수는 사용자 명시 요청 때만 적용한다. 이때 기존 다중 역할 계약을 사용하며 직접 제작의 간소화 규칙으로 필요한 검수를 건너뛰지 않는다.

## 시간과 종료

- 시간을 절약할 때는 불필요한 설명 확장·자료 재독·역할 인계·보고서·미세 디자인 조정부터 생략한다. 원자료 누락이나 오류를 숨겨서 시간을 맞추지 않는다.
- 자체 점검 뒤 중대한 오류가 없으면 완료한다. 이미 통과한 검사를 다시 반복하거나 새 독립 검수를 자동 호출하지 않는다. 해결 불가능한 문제는 위치와 한계를 보고한다.
- 서브 에이전트는 기본 사용하지 않는다. 별도 검토가 꼭 필요한 특정 문제가 남으면 사용자에게 추가 검토를 제안하고, 요청받은 경우에만 사용한다.
