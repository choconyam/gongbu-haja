# 노션 출력 계약

사용자가 노트를 노션으로 받겠다고 할 때만 읽는다. 기본 출력(자료 충실형 Markdown, 심화 이해형 PDF)은 바뀌지 않는다. 자료 충실형은 Markdown 노트를, 심화 이해형은 PDF를 만든 그 TeX 원고를 그대로 올린다.

## 토큰과 연결

- 처음 한 번은 사용자가 직접 한다: 노션 개발자 도구에서 연결(인증 방법 API 토큰, 콘텐츠 읽기·업데이트·입력만) 만들기, 자기 터미널에서 `gongbu notion login`, 상위 페이지를 만들어 그 연결 추가. 연결은 사용자가 연결해 준 페이지 아래에만 쓸 수 있어 첫 상위 페이지는 에이전트가 만들 수 없다. 절차는 `../docs/install.md`의 노션 절이다.
- 에이전트는 토큰을 묻거나 채팅으로 받지 않고, 읽거나 출력하지 않으며, `login`을 실행하지 않는다. 토큰이 없다는 오류가 나면 사용자에게 위 절차를 안내한다.
- 과목 연결은 과목 폴더에서 `gongbu notion setup <상위 페이지 링크> --course <과목명> [--slides yes|no]`이다. 상위 페이지 아래에 과목 페이지를 만들고, 차시 노트는 그 과목 페이지의 하위 페이지로 올라간다(`상위 › 과목 › 차시`). 웹에 공개된 상위 페이지는 거부한다. 페이지 ID와 슬라이드 답만 `.gongbu/notion.json`에 남는다.
- 예전 방식(과목 페이지 안의 "차시별 노트" 표)으로 연결된 과목은 `push`가 멈춘다. `setup`을 한 번 다시 실행하면 과목 페이지는 그대로 두고 차시 페이지 방식으로 바뀐다. 노트를 다시 올린 뒤 예전 표는 사용자 확인을 받고 지운다.
- 교안 슬라이드 그림은 기본으로 함께 올린다. 웹에 공개된 상위 페이지는 `setup`이 거부하므로 비공개 페이지에만 올라간다. 에이전트는 과목마다 따로 묻지 않는다. 사용자가 어떤 과목에서 빼라고 할 때만 `setup --slides no`로 끄며, 그 과목은 그림 자리에 `원본 PDF p.N` 글자만 남는다.

## 원고

- 지금의 자료 충실형 Markdown을 그대로 쓴다. 맨 앞 `# 과목 N주차 — 주제`가 차시 페이지 제목(`N주차 · 주제`)이 되고, `##` 차시 제목들은 페이지 맨 위 회색 머리 줄(모드 · 교안 · 내용)에 들어간다. 노션에서는 제목 단계를 하나씩 올린다(`##` → 제목 1).
- 강조 상자는 `> [!NOTE]`(💡 파랑), `> [!WARNING]`(⚠️ 주황), `> [!TIP]`(📌 초록)으로 쓰고, 첫 줄을 `**이름**`으로 쓰면 상자 제목이 된다. 예전 `> 주의:` 상자도 주황 상자로 간다.
- 불확실성 표시(`[확인 필요]`, `[전사 불명확]` 등)는 노란 형광으로 올라간다. 추적 주석과 인계 메모는 올리지 않는다.
- 로컬 파일 링크는 글자만 남고, 그림은 캡션 글자만 올라간다. 수식 하나는 1000자까지다.

## 심화 이해형 TeX

- 새 원고를 쓰지 않는다. PDF를 빌드한 최종 TeX(진도별이면 `\input`으로 부분을 묶은 문서)를 `push`에 그대로 준다. 표지 `\gongbucover`의 차시가 페이지 제목, 요약이 머리 줄의 내용이 되고, 교안 범위는 슬라이드 쪽 범위로 채운다.
- 절 번호와 식 번호는 PDF와 같게 붙는다. `\eqref`는 그 번호로 바뀐다. 강조 상자는 색 상자로, 각주는 끝의 '각주' 목록으로 간다. 쪽 나눔 명령은 버린다.
- 모르는 환경은 `주의:`로 알리고 안의 내용만 옮긴다. 수식은 노션 수식 엔진(KaTeX)이 그리므로 올린 뒤 노션에서 수식과 그림을 직접 확인한다. KaTeX의 array는 열 지정으로 `l c r | :`만 받으므로 `@{…}`는 그 내용만 든 열로, `p{…}`는 `l`로, `*{n}{…}`는 펼쳐서 옮긴다.

## 올리기

1. `gongbu notion check <노트.md>`로 네트워크 없이 변환·검사한다. `오류:`가 있으면 원고를 고친다.
2. `gongbu notion push <노트.md> --dry-run`의 위치·할 일·내용을 사용자에게 보여 주고 확인을 받는다. 노션은 외부 서비스이므로 확인 없이 올리지 않는다. 이전 확인을 다른 노트에 재사용하지 않는다.
3. `gongbu notion push <노트.md>`(교안 범위를 알면 `--handout "교안 01·02"`)로 올리고 페이지 링크를 전달한다. 올린 페이지는 사용자가 노션에서 열어 확인한다. 검사 통과는 시각 확인이 아니다.

새 차시는 과목 페이지 맨 아래에 붙는다. 다시 올리면 Python이 정한다: 그대로면 건너뛰고, 제목·머리 줄만 바뀌면 그것만 고친다. 원고가 바뀌었고 노션에서 아무도 고치지 않았으면 같은 페이지(자리·링크 그대로)의 내용을 새 블록으로 바꾼다. 노션에서 글자·구조·서식을 고쳤으면 수정이 두 페이지로 갈라지지 않게 새 페이지를 만들지도, 덮어쓰지도 않고 멈춘다. 빈 문단만 생긴 것(노션에서 빈 곳을 누르면 생긴다)은 고친 것으로 보지 않는다. 새 페이지를 만들다 실패하면 그 페이지를 휴지통으로 보내고, 내용을 바꾸다 실패하면 페이지를 남겨 두고(제목이 `업로드 중 · `으로 남는다) 다음 `push`에서 다시 바꾼다. 로컬 원고는 그대로 둔다. 차시 순서는 사용자가 노션 사이드바에서 끌어 바꾼다.

원고가 원본이고 노션은 사본이다. 에이전트는 차시 페이지 본문을 노션에서 직접 고치지 않고 원고를 고쳐 `push`한다. 노션에서 고친 흔적으로 멈추면 그 페이지를 읽어(노션 MCP의 fetch나 API) 원고와 다른 곳을 찾는다. `push --dry-run`이 원고도 마지막으로 올린 뒤 바뀌었는지 알려 주며, 원고가 그대로면 다른 곳이 곧 노션에서 고친 내용이다. 그 수정을 원고(Markdown·TeX)에 옮기고 바뀐 부분을 사용자에게 보여 확인을 받은 뒤 `push --overwrite`로 같은 페이지를 바꾼다. 사용자가 노션의 수정을 버리라고 할 때도 `--overwrite`를 쓴다.

녹음, 전사본, source map, 대응표, 내부 작업 기록은 올리지 않는다.
