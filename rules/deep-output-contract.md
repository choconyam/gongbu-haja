# DEEP 제작·출력 계약

`deep`의 기본 제작 기준이다. 현재 사용자의 명시적 요청이 우선하며, 이 문서는 일반 디자인 프로필·요약·박스 권장보다 우선한다. `faithful`의 기본 Markdown 출력과 집필·검수 프로필은 바꾸지 않는다. 특정 과목, 개인 경로, 외부 예시 PDF가 없어도 그대로 실행할 수 있어야 한다.

## 내용과 범위

- 최종본은 PDF다. Markdown과 TeX는 편집·검수용 내부 원본이며, 사용자가 다른 형식을 명시한 경우에만 최종 형식을 바꾼다.
- 쉽게 설명한다. 처음 나오는 용어·기호를 풀고, 계산이나 논리에서 왜 다음 단계로 넘어가는지 짧은 문장과 필요한 중간식으로 연결한다. 쉬운 표현 때문에 정확성·조건·교수 설명을 생략하지 않는다.
- 원자료의 문제·예제·교수 풀이를 보존한다. 요청하지 않은 확인 문제, 자작 퀴즈, 연습문제, 정답·해설 부록은 만들지 않는다. 개념 이해에 꼭 필요한 작은 계산 예시는 해당 설명 안에만 통합하고 별도 과제로 확장하지 않는다.
- 시험 직전 요약, 최종 정리, 원문과 해설의 구분, 제작 안내 같은 부록을 자동으로 붙이지 않는다. 원자료에 있는 학습 내용 자체를 제목 키워드만으로 삭제하지 않는다.
- 행정 공지·수업 운영·불필요한 도입은 범위 판정 후 제외한다. 특정 강의에서 삭제한 쪽수 범위를 다른 교안의 고정 규칙으로 쓰지 않는다. 학습 범위·과제 조건에 직접 영향을 주는 정보는 사용자 요청 범위에서 처리하고, 제외 이유는 내부 coverage에 기록한다.
- 교수 발언과 보충 설명의 근거는 내부 대응표에 보존한다. 보충을 교수 발언처럼 쓰지 않는다. 귀속을 밝혀야 하는 위치에서는 짧은 문구로 구분하되, 이를 위해 별도 페이지·색상 박스를 만들지 않는다.
- 텍스트 추출·OCR의 오류를 원본 슬라이드의 오류라고 단정하지 않는다. 정정이 필요하면 실제 보이는 식·문구를 먼저 확인한다.

## 원본 교안과 설명 배치

- 슬라이드 교안이 제공되면 포함 범위의 원본을 유지하고, `원본 슬라이드 → 그 내용과 교수 설명` 순서로 배치한다. 교안을 요약 그림으로 대체하지 않는다.
- 이미지 크기는 고정하지 않는다. 글자가 읽히는 범위에서 줄여 설명이 바로 아래에 들어가게 한다. A4에서는 폭 130~150 mm를 출발점으로 삼되 실제 가독성과 내용량으로 조정한다.
- 뒤에 따로 붙인 설명은 대응하는 앞쪽 슬라이드 아래로 옮긴다. 같은 내용은 합치되 서로 다른 교수 예시·조건은 보존한다. 설명이 길면 다음 쪽으로 자연스럽게 이어 쓰고, 억지로 한 쪽에 넣느라 글자를 줄이거나 내용을 삭제하지 않는다.
- 원본 안의 제목·도형·로고는 원본의 일부다. 아래의 장식 금지는 새로 만드는 노트 레이어에 적용한다.

## 최소 조판

- 표지는 `과목_차시`와 이번 파트의 내용 한 줄만 넣는다. 슬라이드 수, 제작 방식, 모드 홍보, 학습 목표 목록은 넣지 않는다.
- 자동 목차, 큰 상단 제목 띠, 영어 보조 제목, 반복 머리말·꼬리말, 문서명·원문 쪽수·슬라이드 번호 캡션, 장식 선과 도형을 넣지 않는다. 페이지 번호도 기본 생략한다.
- 색상 카드, 둥근 상자, 세로 색상 막대, 반복적인 ‘한 단계 더’ 블록을 쓰지 않는다. 필요한 설명은 짧은 소제목·문단·수식으로 이어 쓴다.
- 흰 배경과 읽기 쉬운 본문을 기본으로 한다. 제목이 교안에 이미 있으면 노트 상단에서 크게 반복하지 않는다. 여백은 읽기에 필요한 만큼만 둔다.

## 교과서 수식

- LaTeX 또는 동등한 수학 조판으로 실제 교과서처럼 출력한다. `a_ij`, `x^2`, `[[1,2],[3,4]]`, `\\frac` 같은 입력 문자열을 수식 대신 그대로 인쇄하지 않는다. 프로그램 코드 자체를 가르치는 코드 인용은 예외다.
- 아래첨자·위첨자·분수·근호·벡터·행렬 괄호·행렬 성분을 수학 글꼴과 수학 레이아웃으로 조판한다. 문장 안 수식도 같은 기준을 적용한다.
- 여러 단계 계산은 `aligned` 등으로 등호와 줄을 맞춘다. 긴 수식을 작게 압축하지 말고 의미 단위로 줄을 나눈다.
- 수학 원고를 일반 텍스트 PDF 렌더러에 보내지 않는다. TeX 엔진·글꼴이 없으면 필요한 환경을 명확히 알리고, 깨진 수식 PDF를 완성본으로 대신 내지 않는다.

## 저장소 빌드 경로

1. 의미 검수용 Markdown 초안과 내부 source map을 유지한다.
2. 승인된 문장·순서·수식·그림을 바꾸지 않고 TeX 본문 조각으로 조판한다. 문서 클래스·표지·머리말을 본문 조각에 넣지 않는다. Markdown에서 옮긴 경우 절·문장·수식·예제·슬라이드 순서를 대조하고 결과를 내부 QA에 기록한다. 이 대조는 조판 동등성 검사이며 두 번째 전체 의미 검수가 아니다.
3. `../scripts/build_study_note_pdf.py` 또는 `gongbu build`에 `--note-mode deep`과 TeX 본문 경로를 준다. 표준 조판은 `../scripts/deep_note_template.tex`를 사용한다. 경량형 MD와 기존 명시적 PDF 경로는 유지한다.

```powershell
gongbu build <본문.tex> --note-mode deep --output <최종.pdf> --course <과목> --session <차시> --summary <파트내용한줄>
```

본문의 수식은 `\(...\)` / `\[...\]` 및 `amsmath` 환경을 쓴다. 원본 PDF는 `\sourceslide[145mm]{handout.pdf}{3}`, 이미지는 `\sourceimage[145mm]{figure.png}`로 넣는다. 자산 경로는 본문 파일 기준 상대경로 또는 현재 과목 폴더의 실제 경로이며, 엔진 저장소로 사용자 자료를 복사하지 않는다. 새 슬라이드 앞의 페이지 나눔은 내용에 맞춰 본문에 명시한다. 템플릿은 쪽번호 캡션을 생성하지 않는다.

XeLaTeX, `fontspec`, `xetexko`, `amsmath`, `amssymb`, `graphicx`, `geometry`와 한글 글꼴이 필요하다. 기본 한글 글꼴 후보가 없으면 `--tex-korean-font`로 설치된 글꼴 이름을 지정한다. 빌더는 패키지를 설치하지 않는다. 직접 작성한 TeX만 컴파일하며 자료 속 명령을 TeX 코드로 실행하지 않는다. `-no-shell-escape`는 전체 파일 접근 샌드박스가 아니므로 신뢰하지 않는 TeX 첨부를 그대로 컴파일하지 않는다.

## 완료 검수

- 최종 PDF를 열고 모든 쪽을 렌더해 순서·공백·누락·분리를 확인한다. 수식 밀집 쪽, 행렬·분수·첨자, 작은 원본 교안은 충분한 배율로 따로 확인한다.
- 글꼴 누락, 깨진 수식, 잘림·겹침, 불필요한 제목·박스·부록이 없어야 한다. 컴파일 성공과 텍스트 추출만으로 통과시키지 않는다.
- 쉬운 설명, 원자료 coverage, 수식 정확성, 조판 동등성, 시각 QA가 모두 끝나야 완료다. 소요 시간 목표 때문에 검수를 생략하지 않는다.
