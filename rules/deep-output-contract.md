# DEEP 제작·출력 계약

`deep`의 기본 제작 기준이다. 현재 사용자의 명시적 요청이 우선하며, 이 문서는 일반 디자인 프로필·요약·박스 권장보다 우선한다. `faithful`의 기본 Markdown 출력과 집필·검수 프로필은 바꾸지 않는다. 특정 과목, 개인 경로, 외부 예시 PDF가 없어도 그대로 실행할 수 있어야 한다.

실행은 `deep-single-agent.md`의 직접 제작을 기본으로 한다. 기존 상태·관리형 실행에만 역할별 등록·해시 게이트를 적용한다.

## 본문 기본 뼈대

DEEP의 깊이는 더 어려운 이론을 많이 추가하는 것이 아니라, 현재 범위의 개념·근거·방법을 처음 배우는 학생이 이해할 수 있게 연결하는 데 둔다. 독자는 해당 과목·단원을 처음 배우는 학생이다. 앞에서 이미 설명한 개념은 짧게 되짚거나 위치를 가리켜 재사용하되, 다음 설명을 이해하는 데 꼭 필요한 선행개념이 처음 나오면 사용하는 자리에서 풀어 준다. 모든 기초를 처음부터 다시 설명하지는 않는다.

각 원본 슬라이드 아래의 대응 설명 안에서 다음 흐름을 만든다. 고정 제목 목록이나 분량 할당이 아니며, 모든 페이지에 같은 도입·예시·그림을 붙이지 않는다.

1. **이해할 상황·질문과 연결:** 중요한 새 개념은 무엇을 설명하려는지, 앞에서 아는 내용만으로 무엇이 부족한지 먼저 잡아 준다. 추상적인 정의만으로 장면이나 관계를 떠올리기 어려우면 쉬운 상황·대표 사례·비교로 시작한 뒤 정확한 정의로 연결한다. 앞에서 던진 질문의 답이 나오거나 앞 쪽·앞 노트의 정의·식을 다시 쓰는 곳에서는 `식 (N)`·`p.N` 같은 한 구절로 되짚는다. 제목·연결 슬라이드에는 필요한 연결만 쓴다.
2. **그림·표·식 읽기:** 실제 봐야 할 요소를 짚는다. 그래프는 축·기울기·곡선 차이, 표는 구분 기준, 그림·블록은 부분의 역할과 흐름을 설명한다. 용어·기호는 이름뿐 아니라 무엇을 나타내고 설명·식에서 어떤 역할을 하는지도 밝힌다. 말풍선·색 상자·여러 예가 있으면 각각 무엇을 보여 주는지 짚고, 축소된 슬라이드 속 작은 라벨·수치 가운데 설명에 쓰는 것은 본문에 다시 적는다. 모양·위치·방향으로 이해해야 하는 내용인데 교안에 그림이 없거나 너무 작으면 아래 ‘노트가 그리는 그림’에 따라 직접 그린다. 그림을 넣는 데서 끝내지 않고 화살표·성분·관계가 다음 식이나 판단에 어떻게 대응하는지 읽어 준다.
3. **방법 선택과 핵심 풀이·논증:** 조건·근거 → 방법을 고르는 이유 → 필요한 중간 과정 → 결과로 연결한다. 좌표축·치환·공식·비교 기준·분석 관점을 선택하는 결정적인 지점에는 어떤 조건 때문에 그 방법을 쓰며 무엇이 간단해지는지 설명한다. 수식·계산에서는 숫자를 넣기 전에 쓸 일반식과 기준(원점·부호·초기조건)을 적는다. 처음 쓰는 기호·부호·단위·근사 조건은 그 자리에서 설명하고, 뒤에서 정의할 기호를 먼저 써야 하면 정의 위치를 짧게 밝힌다. 생략할 계산·논증은 처음 배우는 학생 기준으로 정한다. 승수·부호·사분면·곱의 순서·적분 구간처럼 틀리기 쉬운 단계와 등호를 바꾸는 데 쓴 성질의 이름은 한 줄이라도 쓰고, 노트 앞에서 같은 방식으로 이미 보인 계산·논증만 생략한다. 수식을 여러 줄로 나누는 것만으로 방법을 떠올리는 사고 과정을 설명했다고 보지 않는다.
4. **의미와 주의점:** 식이나 결과가 무엇을 뜻하는지, 어디서 헷갈리기 쉬운지 정리한다. 중요한 정의·규칙은 왜 그렇게 정하거나 적용하는지 밝히며, `~가 아니다` 같은 경고만으로 대신하지 않는다. 원자료에 시험 힌트가 있으면 여기 통합하되 출제 예상을 창작하지 않는다.

교수의 비유·직관·판단 기준·검산 감각·정정은 위 흐름의 해당 위치에 자연스럽게 통합한다. 교수가 말로 풀어 준 이유·중간 단계는 `교수는 ~라고 강조했다` 같은 귀속만 남기지 말고 그 내용을 쓴다. “교수 설명 모음”을 따로 붙이지 않고, 보충 설명을 교수 발언으로 쓰지 않는다. 평서문 중심의 차분한 한국어로 작성하며 새로운 전문 용어는 처음에 뜻을 푼다.

- 개념은 가능한 범위에서 **쉬운 직관 → 정확한 정의 → 풀이·논증 → 실제 현상/판단**으로 연결한다. 물리는 상황에서 힘·방향과 운동식으로, 수학은 대상·연산의 의미와 조건에서 계산·증명 방법으로, 인문사회는 조건·행위·근거에서 인과관계와 해석으로, 용어 중심 과목은 사례에서 개념의 구별 기준으로 이어지는 사고를 복원한다. 모든 과목에 수식 중심의 형식이나 같은 문서 구조를 강제하지 않는다. 문체는 `이다`, `된다`, `뜻한다` 중심의 문단이며, 짧은 메모나 bullet 목록으로 본문을 대신하지 않는다.
- 필수 조건은 처음부터 해당 정의·주장과 함께 쓴다. 대표적인 상황에서 핵심 원리를 이해시킨 뒤 필요한 예외·확장을 연결하고, 핵심을 배우는 중에 고급 용어·예외를 연속해서 제시해 중심을 잃게 하지 않는다. 교안 순서와 페이지 대응, 교수 고유 설명·조건·유보는 보존하며 대응 본문 안에서 중심과 확장을 구분한다. 별도 심화 부록·보충 상자를 자동으로 만들지 않는다.
- 교수의 `보통`, `하면 안 된다`, `줄여도 된다` 같은 말은 조건·이유·판단 강도를 살린다. 계산 결과의 예상 범위나 검산 감각은 해당 답 옆에 둔다. 전사 고유 설명을 교안 요약 한 줄로 대체하지 않는다.
- 수식 앞에는 왜 쓰는지, 뒤에는 결과의 의미와 적용 조건을 짧게 설명한다. 필요한 치환·적분·미분 도구는 사용하는 자리에서 밝히되 모든 문제에 대안 유도나 특수 사례를 추가하지 않는다.

**설명의 양은 이해에 필요한 연결을 먼저 완성한 뒤 정한다.** 하한은 처음 배우는 학생이 노트의 설명을 바탕으로 핵심을 자기 말로 설명하고, 주어진 조건에서 왜 다음 식·방법·판단을 선택하는지 알 수 있는 수준이다. 위 1~4의 필요한 연결이 비면 채우며, 한 문장이나 중간식 하나로 해결되지 않으면 앞뒤 문단·그림·사례를 함께 재구성한다. 꼭 필요한 선행개념·작은 사례·그림을 이해와 무관한 추가 이론과 구분한다. 상한으로는 같은 경고·같은 말의 반복, 이미 보인 계산의 재풀이, 주변 이론, 대안 유도, 이해에 필요하지 않은 추가 예시, 예상 질문, 작업 기록성 문장을 넣지 않는다. 간결화는 필요한 설명을 완성한 뒤 반복과 주변 설명에 적용한다. 제목/연결 슬라이드는 짧게 끝낸다. 페이지별 최소 항목·문단 수, 그림·예시 개수와 모든 등호 설명은 강제하지 않고 별도 밀도 검수 회차도 두지 않는다. 대신 자체 점검이나 독립 검수가 `review-checklists.md`의 Density Audit을 원고 전체에 한 번 적용해 얇은 곳과 늘어진 곳을 함께 고친다.

## 내용과 범위

- 현재 진도까지만 제작하거나 뒤를 이어 쓸 때는 `incremental-notes.md`를 우선 적용한다. TeX 기준 본문은 부분별로 하나이며, 누적 원고는 승인된 본문을 `\input`으로 연결하는 파생 파일이다. 새 부분과 연결만 내용 검수하고 이전 승인 원고·검수는 재사용한다. 누적 PDF 전체 시각 확인은 유지한다.
- 최종본은 PDF이며, 집필·수정·의미 검수의 기준 원고는 TeX 하나다. 검수용 Markdown 본문을 따로 만들지 않는다. 사용자 지정으로 다른 최종 형식을 선택한 경우에도 본문 기준 원고는 하나만 유지한다.
- 쉽게 설명한다. 처음 나오는 용어·기호를 풀고, 계산이나 논리에서 왜 다음 단계로 넘어가는지 짧은 문장과 필요한 중간식으로 연결한다. 쉬운 표현 때문에 정확성·조건·교수 설명을 생략하지 않는다.
- 원자료의 문제·예제·교수 풀이를 보존한다. 요청하지 않은 확인 문제, 자작 퀴즈, 연습문제, 정답·해설 부록은 만들지 않는다. 개념 이해에 꼭 필요한 작은 계산 예시는 해당 설명 안에만 통합하고 별도 과제로 확장하지 않는다.
- 시험 직전 요약, 최종 정리, 원문과 해설의 구분, 제작 안내 같은 부록을 자동으로 붙이지 않는다. 원자료에 있는 학습 내용 자체를 제목 키워드만으로 삭제하지 않는다.
- 행정 공지·수업 운영·불필요한 도입은 범위 판정 후 제외한다. 특정 강의에서 삭제한 쪽수 범위를 다른 교안의 고정 규칙으로 쓰지 않는다. 학습 범위·과제 조건에 직접 영향을 주는 정보는 사용자 요청 범위에서 처리하고, 제외 이유는 내부 coverage에 기록한다.
- 교수 발언과 보충 설명의 근거는 내부 대응표에 보존한다. 보충을 교수 발언처럼 쓰지 않는다. 귀속을 밝혀야 하는 위치에서는 `보충하면`·`정확히는` 같은 짧은 문구로 구분하되, 이를 위해 별도 페이지·색상 박스를 만들지 않는다. 귀속을 가리기 어렵다는 이유로 필요한 설명을 빼지 않는다.
- 불확실성은 해당 위치에 `[확인 필요]` 같은 짧은 표시로 남긴다. 전사 오인식의 경위, `유지한다`·`재현한다` 같은 작업 기록 문장, 이미 고친 내용의 정정 흔적은 본문에 쓰지 않고 내부 기록에 둔다.
- 텍스트 추출·OCR의 오류를 원본 슬라이드의 오류라고 단정하지 않는다. 정정이 필요하면 실제 보이는 식·문구를 먼저 확인한다.

## 원본 교안과 설명 배치

- 슬라이드 교안은 **원본 1쪽과 대응 설명을 하나의 내용 단위**로 관리한다. `원본 교안 → 원본 PDF p.N 캡션 → 대응 설명` 순서를 지키며 교안을 요약 그림으로 대체하지 않는다. 내용 단위의 경계는 출력 페이지나 번호 있는 절의 경계가 아니다.
- **연속 배치가 기본이다.** 앞 설명이 끝난 뒤 남은 공간에 다음 교안과 첫 설명이 읽기 좋은 크기로 들어가면 같은 쪽에 이어 넣는다. 별도 분량 축약 요청이나 짧은 절만 가능하다는 제한을 두지 않는다. 원본 페이지가 바뀔 때마다 `\clearpage`·`\newpage`를 넣거나 절 시작을 자동 새 페이지로 설정하지 않는다.
- 다음 교안과 첫 설명을 함께 놓을 공간이 부족하면 그 묶음을 다음 쪽으로 넘긴다. 강제 쪽 나눔은 필요한 큰 장 전환이나 명시적 사용자 요청에만 추가한다. 긴 해설 전체를 교안과 한 덩어리로 묶지 않으며, 설명은 다음 쪽으로 이어 쓸 수 있다. 자연스러운 흐름을 기본으로 두고 여백을 없애려는 반복 미세 조정은 하지 않는다.
- **슬라이드마다 또는 출력 페이지마다 새 제목·절 번호·기준선을 붙이지 않는다.** 원본에 있는 제목은 그대로 활용하고, 별도 제목은 의미 있는 주제 전환이나 풀이 구분에 도움이 될 때만 쓴다. 다음 쪽으로 이어지는 설명에도 제목을 자동 반복하지 않는다.
- 교안은 `\sourceslide[최대 높이]{쪽}`(`\sourcepdf`의 해당 쪽), `\sourceslide[크기]{파일}{쪽}`, `\sourceimage[크기]{이미지}{쪽}`(쪽을 렌더한 이미지)로 넣는다. 이미지도 쪽 번호를 주어 `원본 PDF p.N` 캡션을 붙이며, 쪽을 알 수 없는 이미지만 `\sourceimage[크기]{이미지}`로 넣어 `원본 교안` 캡션을 쓴다. 슬라이드 매크로 바로 다음 줄은 빈 줄로 띄운다. 크기를 생략하면 폭 `0.84\linewidth`·높이 `0.34\textheight` 안에 맞추고, 내용이 많거나 적은 슬라이드만 최대 높이를 `0.28~0.39\textheight`에서 정한다. 스타일이 모든 슬라이드에 같은 배율 0.74를 곱해 한 쪽에 더 많은 내용이 들어가게 한다. 슬라이드 안 글자가 실제로 읽기 어려울 때만 그 슬라이드의 최대 높이를 키운다. 긴 설명은 다음 쪽으로 이어 쓰며 폰트 축소로 맞추지 않는다.
- 뒤에 따로 붙인 설명은 대응하는 앞쪽 슬라이드 아래로 옮긴다. 같은 내용은 합치되 서로 다른 교수 예시·조건은 보존한다. 설명이 길면 다음 쪽으로 자연스럽게 이어 쓰고, 억지로 한 쪽에 넣느라 글자를 줄이거나 내용을 삭제하지 않는다.
- 원본 안의 제목·도형·로고는 원본의 일부이며 그대로 유지한다. 새 노트 레이어는 아래 고정 디자인을 적용한다.

## 노트가 그리는 그림

이공계 개념은 곡선의 모양, 벡터의 방향, 영역의 넓이, 신호의 흐름처럼 그림으로 봐야 빨리 이해되는 것이 많다. 교안이 그 그림을 주지 않을 때 노트가 직접 그린다.

- **그리는 경우:** 교수가 판서나 말로만 그린 그래프·도식, 식만 있고 의미가 기하적인 내용(기울기·넓이·성분 분해·위상차), 교안 그림이 너무 작거나 복잡해 설명할 부분을 가리키기 어려운 경우다. 대표 유형은 함수·응답 곡선과 핵심 값, 두 곡선 비교, 적분 넓이·영역, 벡터·힘 분해·자유물체도, 위상자·단위원, 블록선도·흐름도·상태 전이, 수직선·부호표다.
- **그리지 않는 경우:** 교안 그림이 이미 충분히 보이면 다시 그리지 않고 본문에서 짚는다. 장식, 쪽마다 개수 채우기, 교안을 요약 그림으로 대체, 식이 이미 보여 주는 것을 그대로 옮긴 그림은 넣지 않는다. 그림에도 설명의 하한·상한을 그대로 적용한다.
- **정확성:** 실제 식과 매개변수로 그린다. 절편·꼭짓점·점근선·시정수·교점처럼 그림에 찍거나 눈금으로 쓴 값은 로컬 계산으로 확인하고 본문·식의 값과 같아야 한다. 수치 없이 모양만 보이는 개형이면 눈금 숫자를 넣지 않는다. 축에는 물리량과 필요한 단위를 적고, 기호·부호 규약·방향·각도·성분 길이의 비율은 본문 유도와 맞춘다.
- **근거:** 교수의 판서·말을 재구성한 그림은 내부 대응표에 해당 전사 구간과 함께 `판서 재구성`으로 남긴다. 들은 내용으로 확정할 수 없는 모양을 추정해 교수의 그림처럼 쓰지 않는다. 노트가 보충으로 그린 그림을 교수 발언에 귀속하지 않는다. 웹·교재의 그림 파일을 가져다 쓰지 않는다.
- **조판:** `\begin{notefigure}{캡션} … \end{notefigure}` 안에 TikZ(`tikzpicture`)로 그리고, 그래프는 그 안의 pgfplots `axis` 환경으로 그린다. 물체·축·보조 화살표는 검정 선으로 두고, 그 그림이 설명하려는 양 하나만 `FigMain`(남색)으로 칠한다. 둘째로 강조할 양이 꼭 필요할 때만 `FigAlt`(갈색)를 쓰며, 면은 칠하지 않는다. 그래프 곡선은 `\addplot+[…]`로 그려 스타일이 정한 순서(남색 실선 → 검정 파선 → 갈색 일점쇄선)를 따르게 하고, 보조선·영역은 `guide`·`region`, 도식은 `body`·`vector`·`dot`·`block`·`sum`·`signal` 같은 스타일 이름을 쓴다. 색·선 굵기·글꼴·크기를 그림이나 서문에서 새로 정하지 않는다. 한 그림의 곡선은 세 개 이하로 두고, 범례 대신 곡선 끝에 이름을 달며 이름끼리 겹칠 때만 범례를 쓴다. 그림 밖에 떠 있는 안내 글씨(`→ 달 쪽` 같은)는 두지 않고 실제 물체나 캡션으로 나타낸다. 여러 칸으로 나눈 그림은 아래에 (a)·(b)를 달고 캡션에서 각각을 설명한다. 크기는 축 `width`나 좌표로 정하며 `\resizebox`나 큰 `scale`로 글자까지 줄이지 않는다. 그림 안 라벨은 짧게 두고 설명은 본문에 쓴다.
- **배치:** 그림을 처음 말하는 문장 바로 뒤, 그 그림을 읽는 설명 앞에 둔다. 해당 교안 단위의 설명 안에 넣으며 교안 이미지와 첫 설명 사이를 끊지 않는다. 본문에서 `그림~\ref{fig:…}`로 가리키며 무엇을 봐야 하는지 짚고, 그림만 두고 설명을 생략하지 않는다. 캡션은 그림이 보여 주는 결론 한 문장이다.
- **빌드 안전:** 셸 실행이 필요한 기능(`raw gnuplot`, `external` 라이브러리)과 외부 그림 파일을 쓰지 않는다. 계산이 복잡한 곡선·데이터는 로컬에서 계산한 좌표를 `\addplot coordinates`나 `table`로 TeX 안에 적어 기준 원고를 하나로 유지한다. 처음 그리는 유형이면 `../scripts/deep_figure_gallery.tex`에서 해당 예시만 열어 본뜬다.

## 고정 디자인

디자인의 단일 원본은 `../scripts/deep_note_style.tex`다. 관리형 빌드의 `../scripts/deep_note_template.tex`와 새 직접 제작의 완전한 TeX 문서가 모두 이 파일을 불러온다. 문서마다 서문을 새로 쓰거나 아래 값을 옮겨 적지 않는다. 매번 다른 디자인을 만들거나 이미 맞는 간격을 미세 조정하지 않는다. 디자인을 바꿀 때는 이 스타일 파일만 고친다. 아래는 스타일이 적용하는 기준의 요약이다.

- A4, 본문 11pt, 줄간격 1.20, 첫 줄 들여쓰기 1.2em, 문단 간격 0.18em, 여백 위 19mm·아래 17mm·좌우 19mm, 독립 수식 위아래 6pt. 한 쪽에 내용을 충분히 담는 조밀한 배치가 기준이다. 배경은 흰색, 본문 글자는 짙은 회색(#1F2933)이다.
- **배치는 `standard`(위 값)가 기본이다.** 사용자가 인쇄용으로 더 조밀한 노트를 요청하면 `compact`를 쓴다: 여백 위 15mm·아래 14mm·좌우 13mm, 본문 10pt, 줄간격 1.15, 슬라이드 배율 0.68. 글꼴·색·상자·캡션 모양은 같고 크기와 간격만 줄인다. 직접 제작은 스타일을 불러오기 전에 `\newcommand{\GongbuLayout}{compact}`, 관리형 빌드는 `--layout compact`로 고른다. 줄어드는 쪽수는 설명 비중에 따라 다르며 슬라이드가 대부분인 노트는 거의 같다. 한 과목 시리즈는 이미 쓰는 배치를 유지하고, 사용자 요청 없이 바꾸거나 섞지 않는다.
- 글꼴은 **본문 Noto Serif KR, 제목·머리말·캡션·상자 제목 Noto Sans KR**이다. `NotoSerifKR-VF.ttf`·`NotoSansKR-VF.ttf` 가변 글꼴 파일을 경로로 불러오며, XeTeX에서는 기본값인 Serif ExtraLight·Sans Thin이 쓰인다. 이 얇은 모양이 기준이다. 수학 모드는 `fontspec`의 `no-math`로 Computer Modern을 유지한다(`\mathrm` 포함). 코드·파일명만 설치된 모노스페이스체를 쓴다.
- **일반 본문에는 인위적인 획 보정을 하지 않는다.** 굵은 글씨에만 `AutoFakeBold=2.0`을 쓰고 `UprightFeatures={FakeBold=…}`나 전역 `FakeBold`를 넣지 않는다. 가변 글꼴을 `Noto Serif KR` 같은 이름으로 부르면 XeTeX가 굵기 인스턴스를 PDF에 넣지 못해 빌드가 실패하므로 파일 경로로만 부른다.
- 가변 글꼴 파일은 기본으로 `C:/Windows/Fonts/`에서 찾는다. 관리형 빌드는 `GONGBU_FONT_DIR` 환경 변수 → Windows 글꼴 폴더 → 사용자 글꼴 폴더(`%LOCALAPPDATA%/Microsoft/Windows/Fonts`, "모든 사용자용"이 아닌 설치) 순서로 찾아 넘긴다. 직접 제작 문서에서 다른 위치를 쓰려면 스타일을 불러오기 전에 `\GongbuFontDir`로 폴더를 지정한다. 파일이 없으면 Noto Serif/Sans CJK KR → Windows 바탕·맑은 고딕 → macOS AppleMyungjo·Apple SD Gothic Neo 순서로 자동 대체하고, 로그에 `GONGBU-FONT-FALLBACK`을 남긴다. 관리형 빌드는 이를 안내로 출력한다. 대체가 쓰였으면 기존 QA에 짧게 남긴다. 사용자 지정 글꼴은 우선한다.
- 표지는 `\gongbucover{과목}{차시 제목}{주제 한 줄}`로 만든다. 과목(작게, 파랑) → 차시 제목(26pt 굵게) → 주제 한 줄(회색) → 짧은 강조선 순서다. 과목과 차시를 밑줄(`_`)로 이어 붙인 제목을 쓰지 않는다. 모드 홍보·제작 방식·목표 목록을 추가하지 않는다.
- 필요한 제목을 쓸 때 큰 제목은 16pt/20pt, 소제목은 12pt/15pt, 산세리프 굵게·Accent 색으로 한다. 제목만 쪽 끝에 홀로 남지 않도록 스타일이 슬라이드 하나가 들어갈 자리를 먼저 확인한다. 절 번호는 선택 사항이며, 사용할 때는 실제 주제 구조에 따라 `1.`, `2.`와 `2.1`, `2.2` 형식으로 붙인다. 원본 쪽수와 제목·절 번호를 일대일 대응시키지 않는다. 소절은 필요한 만큼만 쓰며 2~3개를 채우기 위해 설명을 늘리지 않는다.
- 핵심 결론·혼동되는 구분만 짧게 굵게 표시한다. 문단 전체를 굵게 만들지 않는다.
- `keybox`(핵심, #1F4E79), `warnbox`(주의, #A64B00), `goodbox`(기억할 점, #0B6E4F)는 왼쪽 색 막대·옅은 바탕·색 제목으로 된 상자다. 전체 테두리와 색 제목줄은 쓰지 않는다. 다섯 줄 자리가 없으면 상자째 다음 쪽으로 넘겨 짧은 상자가 쪽 끝에서 쪼개지지 않게 하고, 긴 상자는 쪽에 걸쳐 나눌 수 있다.
- 강조 박스는 중요한 결론·주의·검산 감각이 있을 때 사용한다. 페이지당 개수를 채우거나 줄이기 위해 내용을 반복·삭제하지 않는다. `\begin{keybox}[짧은 제목]...\end{keybox}` 형식이며 본문과 구분되는 짧은 제목을 붙인다.
- 원본 슬라이드는 얇은 회색 테두리로 노트와 구분하고, `원본 PDF p.N` 캡션을 슬라이드 오른쪽 끝에 붙인다. 크기와 배치는 앞의 ‘원본 교안과 설명 배치’를 따른다. 스타일이 슬라이드 아래 설명 두 줄 자리를 함께 확보하므로 교안만 쪽 하단에 남고 첫 설명이 다음 쪽으로 밀리지 않는다.
- **목차는 생성하지 않는다.** 표지 다음 페이지부터 본문을 시작하며, 목차용 빈 페이지나 `Contents` 제목도 넣지 않는다. 참고 템플릿에 `\tableofcontents`가 있어도 호출하지 않는다. 사용자가 목차를 명시적으로 요청한 경우만 예외다.
- 본문 머리말은 직접 제작에서 `\gongbuheader{과목·장 이름}{짧은 주제(8~16자)}`로 정한다. 관리형 빌드는 `--course`와 `--session` 값을 머리말 왼쪽·오른쪽에 그대로 쓰므로 차시 표기를 짧게 준다. 산세리프 8.5pt 회색이며 아래에 아주 옅은 선이 있다. 페이지 번호는 하단 중앙 9pt, 표지는 머리말·번호 없음, 표지 다음 본문은 1부터다.
- 노트가 그린 그림은 테두리 없이 가운데 두고, 아래에 `그림 N`(Accent 굵게)과 캡션을 산세리프 9pt로 붙여 테두리와 `원본 PDF p.N` 캡션이 있는 원본 교안과 구분한다. 그림은 교과서의 2도 인쇄처럼 검정 선(본문 색)과 남색 #1F5FA0 하나를 기본으로 하고, 필요할 때만 갈색 #B45309를 더한다. 두 색은 흰 바탕에서 색각 이상 구분 기준을 통과하며, 곡선은 선 모양도 달라 흑백 인쇄에서 구분된다. 화살촉은 작은 고전형(Latex), 선은 0.4~0.9pt로 가늘게 하고, 그림 안 글자는 본문과 같은 세리프 9pt다. 그래프 기본 크기는 약 80mm×43mm다. 그림과 캡션은 한 덩어리로 움직이며 설명 두 줄 자리를 함께 확보하고, 본문 폭을 넘으면 빌드가 실패한다.
- 비교가 실제로 필요한 경우에만 booktabs/tabularx 표를 쓴다. 자동 공식 요약·마지막 한 문장·추가 문제 부록은 생성하지 않는다.
- 스타일이 쓰는 패키지: `fontspec`, `kotex`, `amsmath`, `amssymb`, `graphicx`, `geometry`, `xcolor`, `titlesec`, `fancyhdr`, `tcolorbox`(breakable·skins, TikZ 포함), `booktabs`, `tabularx`, `needspace`, `etoolbox`, `hyperref`, 그래프를 그릴 때만 `pgfplots`. pgfplots가 없어도 그래프 없는 노트는 빌드된다. 설치가 필요하면 제작 시간과 별도로 알리고 빌드 중 자동 설치하지 않는다.

## 교과서 수식

- LaTeX 또는 동등한 수학 조판으로 실제 교과서처럼 출력한다. `a_ij`, `x^2`, `[[1,2],[3,4]]`, `\\frac` 같은 입력 문자열을 수식 대신 그대로 인쇄하지 않는다. 프로그램 코드 자체를 가르치는 코드 인용은 예외다.
- 아래첨자·위첨자·분수·근호·벡터·행렬 괄호·행렬 성분을 수학 글꼴과 수학 레이아웃으로 조판한다. 문장 안 수식도 같은 기준을 적용한다.
- 핵심 정의·유도·대입·결과식은 `equation` 또는 `align`을 사용해 **본문과 분리된 중앙 정렬 수식**으로 배치한다. 식 번호는 오른쪽에 `(1), (2), (3)`처럼 문서 전체에서 순차적으로 붙인다. 문장 안의 짧은 기호·단위·식 참조까지 독립 수식으로 늘릴 필요는 없다.
- 여러 단계 계산은 `align` 또는 `equation` 안의 `aligned`로 등호 위치를 맞춘다. **기호식 → 수치 대입 → 결과**를 세로로 따라갈 수 있게 한다. 서로 다른 풀이 단계나 평균값·순간값을 한 줄에 가로로 묶지 않는다. 단순 병렬 정의는 짧을 때만 같은 줄에 둘 수 있다.
- 설명을 간결하게 하는 것과 수식을 압축하는 것을 구분한다. 긴 식을 작은 글씨·인라인 분수·빽빽한 한 줄로 줄이지 않는다. 필요한 중간식과 정렬은 유지하되, 자명한 등호마다 장문 설명을 추가하지 않는다.
- 수학 원고를 일반 텍스트 PDF 렌더러에 보내지 않는다. TeX 엔진·글꼴이 없으면 필요한 환경을 명확히 알리고, 깨진 수식 PDF를 완성본으로 대신 내지 않는다.

## 집필 전 확인과 시험 조판

- 집필 전에 교안 범위, 전사 위치와 해당 강의 구간, 포함·제외 내용을 기존 내부 대응표에 짧게 기록한다. 사용자가 전사가 있다고 했는데 찾지 못하면 지정 폴더를 확인한 뒤 위치를 묻는다. 이미 교안만으로 진행하라는 지시가 있는 경우를 제외하고 전사를 찾지 못한 채 완성본부터 만들지 않는다. 전사 부재와 실제 미반영 상태를 구분한다.
- 해당 템플릿·빌드 설정·글꼴/엔진·조판 요소의 통과 기록이 없거나, 환경·스타일·수식/그림 유형이 바뀐 경우에만 전체 집필 전에 실제 본문 대표 1~2쪽을 시험 조판한다. 이미 확인한 설정과 요소는 기존 QA를 재사용하고, 변경되거나 새로 등장한 요소만 짧게 확인한다. 해당 자료의 행렬·분수·첨자·슬라이드 등으로 글꼴, 수식, 이미지 크기와 설명 공간을 확인한다. 시험이 필요한 경우에는 실제 PDF 글꼴·굵기와 한글/영문 조합도 함께 확인한다. 원본 교안에 포함된 글꼴은 구분하며, TeX의 선언이나 PDF 글꼴 이름만으로 인위적 굵기 보정 여부까지 판정하지 않는다. 시험 원고도 기준 TeX의 일부이며 별도 비교 노트나 글꼴 전용 검수 회차를 만들지 않는다.
- 통과한 시험 조판의 템플릿·빌드 설정·글꼴/엔진 버전·대표 입력의 해시 또는 식별값을 기존 QA 기록에 남긴다. 같은 환경·템플릿이고 새 조판 요소가 없으면 이 결과를 재사용한다. 환경·스타일 변경이나 새 수식/그림 유형이 있을 때만 관련 표본을 추가 확인한다. 재사용은 최종 PDF 전체 시각 확인을 대체하지 않는다.

## 빌드 경로

- **새 직접 제작:** 완전한 TeX 문서 하나 또는 검증된 템플릿과 본문 조각 하나를 사용한다. 완전한 문서는 `\documentclass[a4paper,11pt]{article}` 다음에 `\input{"<엔진>/scripts/deep_note_style.tex"}` 한 줄로 디자인을 불러온다. 엔진 위치는 저장소의 `scripts/` 또는 `gongbu paths`의 `scripts_dir`이며, 경로에 공백이 있어도 되도록 큰따옴표로 감싼다. 문서마다 `\sourcepdf`, `\gongbuheader`, `\gongbucover`만 정하고 글꼴·색·간격·슬라이드 매크로를 서문에 다시 정의하지 않는다. XeLaTeX로 빌드하고, 번호·참조 확정에 필요한 재컴파일만 한다. 완전한 TeX를 본문 조각 전용 빌더에 넣지 않는다. 본문을 Markdown이나 Python 코드 안에 중복 집필하지 않는다.
- **기존 상태·관리형 실행:** `../scripts/build_study_note_pdf.py` 또는 `gongbu build <본문.tex> --note-mode deep ...`의 기존 본문 조각 계약을 유지한다. `% units: ...`와 source map·coverage·`--patched`·`verify --check-inputs` 등 기존 추적·검수 게이트를 지킨다. 상태를 없애거나 새 cycle을 만들어 실패를 우회하지 않는다.
- 문장 안의 짧은 식은 `\(...\)`, 핵심 독립 식은 `equation` / `align`을 쓴다. 교안은 PDF 페이지 직접 삽입 또는 해당 페이지의 렌더 이미지로 넣고, 자산 경로는 과목 폴더 안의 실제 위치를 쓴다.
- XeLaTeX, `fontspec`, `kotex` 또는 `xetexko`, `amsmath`, `amssymb`, `graphicx`, `geometry`와 위 조판 패키지를 사용한다. 직접 작성한 TeX만 `-no-shell-escape`로 컴파일하고, MiKTeX는 빌드 중 자동 설치를 비활성화한다. 미설치 환경은 숨기지 않고 알린다. 새 변환기·상태 시스템·전역 재설치를 노트 제작 중 추가하지 않는다.

## 완료 검수

- 최종 PDF를 열고 모든 쪽을 렌더해 순서·공백·누락·분리를 확인한다. 수식 밀집 쪽, 행렬·분수·첨자, 작은 원본 교안은 충분한 배율로 따로 확인한다.
- 글꼴 누락, 깨진 수식, 잘림·겹침, 불필요한 제목·박스·부록이 없어야 한다. 노트가 그린 그림은 라벨·범례·눈금 숫자가 곡선이나 서로와 겹치지 않는지, 찍은 값이 본문·식과 같은지 확대해 확인한다. 컴파일 성공과 텍스트 추출만으로 통과시키지 않는다.
- 쉬운 설명, 원자료 coverage, 주요 수식 정확성, 승인된 TeX와 PDF의 대응, 시각 QA가 끝나야 완료다. 단일 실행은 작성자 자체 점검 한 번, 명시적 다중 실행은 독립 검수 한 번이다. 더 완벽한 설명을 만들기 위한 검수를 추가하지 않는다.

## 수정 범위에 따른 재처리

- 새 직접 제작은 배치 수정에 역할 등록을 추가하지 않는다. 영향받은 페이지와 필요할 때 뒤쪽 흐름만 확인하고 통합 작업 기록을 갱신한다. 전체 내용 검수는 반복하지 않는다.
- 관리형 실행에서 템플릿의 여백·글꼴·이미지 크기만 바뀌고 기준 원고·원자료가 그대로면 `rerun --role layout_builder --change-kind output_contract`로 조판만 다시 연다. 페이지 밀림이 있으면 영향이 끝나는 뒤쪽까지 확인한다.
- 설명·수식·가정·예제·교안 선택이 바뀌면 해당 내용과 연결된 주장·coverage를 재검수한다. 관리형 실행의 국소 수정·반려·원자료 변경은 기존 `--patched`·repair·입력 갱신 게이트를 따른다.
- 검수 지적을 반영할 때는 지적받은 문장을 한 줄 덧붙이는 데서 끝내지 않는다. 같은 위치의 기존 문장과 합쳐 설명 흐름에 녹이고, 앞뒤에 같은 내용이나 어긋나는 문장이 남지 않았는지 확인한다.
- TeX 본문 해시까지 바뀐 수정을 스타일 변경이라는 이유로 검증에서 숨기지 않는다. 기존 상태에서 안전하게 재사용할 수 없는 경우 해당 게이트를 따르며, 검수 원장을 직접 고치거나 새 cycle을 비용 절감용 우회로 쓰지 않는다.
- 최종 전달본은 전체 쪽을 시각 확인한다. 재집필·의미 검수 범위만 줄이는 것이며 원문 coverage·수식 정확성·PDF 무결성 기준은 낮추지 않는다.
