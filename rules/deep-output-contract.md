# DEEP 제작·출력 계약

`deep`의 기본 제작 기준이다. 현재 사용자의 명시적 요청이 우선하며, 이 문서는 일반 디자인 프로필·요약·박스 권장보다 우선한다. `faithful`의 기본 Markdown 출력과 집필·검수 프로필은 바꾸지 않는다. 특정 과목, 개인 경로, 외부 예시 PDF가 없어도 그대로 실행할 수 있어야 한다.

실행은 `deep-single-agent.md`의 직접 제작을 기본으로 한다. 기존 상태·관리형 실행에만 역할별 등록·해시 게이트를 적용한다.

## 본문 기본 뼈대

각 원본 슬라이드 아래에 다음 흐름으로 설명한다. 고정 제목 목록이나 분량 할당이 아니라 내용 구성의 기본 순서다.

1. **핵심 메시지와 연결:** 이 페이지가 무엇을 말하며 왜 여기 등장하는지 1~2문장. 앞뒤 연결은 필요한 곳에만 쓴다.
2. **그림·표·식 읽기:** 실제 봐야 할 요소를 짚는다. 그래프는 축·기울기·곡선 차이, 표는 구분 기준, 그림·블록은 부분의 역할과 흐름을 설명한다. 보이는 이름만 나열하지 않는다.
3. **핵심 풀이·유도:** 문제 조건과 쓸 식 → 필요한 중간 과정 → 답. 처음 쓰는 기호·부호·단위·근사 조건을 가까이에 설명하고 자명한 계산까지 모두 풀지는 않는다.
4. **의미와 주의점:** 식이나 결과가 무엇을 뜻하는지, 어디서 헷갈리기 쉬운지 짧게 정리한다. 원자료에 시험 힌트가 있으면 여기 통합하되 출제 예상을 창작하지 않는다.

교수의 비유·직관·판단 기준·검산 감각·정정은 위 흐름의 해당 위치에 자연스럽게 통합한다. “교수 설명 모음”을 따로 붙이지 않고, 보충 설명을 교수 발언으로 쓰지 않는다. 평서문 중심의 차분한 한국어로 작성하며 새로운 전문 용어는 처음에 뜻을 푼다.

- 개념은 가능한 범위에서 **쉬운 직관 → 정확한 정의 → 수식 → 실제 현상/판단**으로 연결한다. 문체는 `이다`, `된다`, `뜻한다` 중심의 문단이며, 짧은 메모나 bullet 목록으로 본문을 대신하지 않는다.
- 교수의 `보통`, `하면 안 된다`, `줄여도 된다` 같은 말은 조건·이유·판단 강도를 살린다. 계산 결과의 예상 범위나 검산 감각은 해당 답 옆에 둔다. 전사 고유 설명을 교안 요약 한 줄로 대체하지 않는다.
- 수식 앞에는 왜 쓰는지, 뒤에는 결과의 의미와 적용 조건을 짧게 설명한다. 필요한 치환·적분·미분 도구는 사용하는 자리에서 밝히되 모든 문제에 대안 유도나 특수 사례를 추가하지 않는다.

**페이지별 최소 항목·문단 수, 모든 등호 설명, 별도 밀도 검수는 강제하지 않는다.** 제목/연결 슬라이드는 짧게 끝내고, 필요한 유도와 교수 설명만 충분히 남긴다. 질문의 여지를 모두 없애는 해설보다 강의 이해와 복습에 쓸 수 있는 노트를 목표로 한다.

## 내용과 범위

- 현재 진도까지만 제작하거나 뒤를 이어 쓸 때는 `incremental-notes.md`를 우선 적용한다. TeX 기준 본문은 부분별로 하나이며, 누적 원고는 승인된 본문을 `\input`으로 연결하는 파생 파일이다. 새 부분과 연결만 내용 검수하고 이전 승인 원고·검수는 재사용한다. 누적 PDF 전체 시각 확인은 유지한다.
- 최종본은 PDF이며, 집필·수정·의미 검수의 기준 원고는 TeX 하나다. 검수용 Markdown 본문을 따로 만들지 않는다. 사용자 지정으로 다른 최종 형식을 선택한 경우에도 본문 기준 원고는 하나만 유지한다.
- 쉽게 설명한다. 처음 나오는 용어·기호를 풀고, 계산이나 논리에서 왜 다음 단계로 넘어가는지 짧은 문장과 필요한 중간식으로 연결한다. 쉬운 표현 때문에 정확성·조건·교수 설명을 생략하지 않는다.
- 원자료의 문제·예제·교수 풀이를 보존한다. 요청하지 않은 확인 문제, 자작 퀴즈, 연습문제, 정답·해설 부록은 만들지 않는다. 개념 이해에 꼭 필요한 작은 계산 예시는 해당 설명 안에만 통합하고 별도 과제로 확장하지 않는다.
- 시험 직전 요약, 최종 정리, 원문과 해설의 구분, 제작 안내 같은 부록을 자동으로 붙이지 않는다. 원자료에 있는 학습 내용 자체를 제목 키워드만으로 삭제하지 않는다.
- 행정 공지·수업 운영·불필요한 도입은 범위 판정 후 제외한다. 특정 강의에서 삭제한 쪽수 범위를 다른 교안의 고정 규칙으로 쓰지 않는다. 학습 범위·과제 조건에 직접 영향을 주는 정보는 사용자 요청 범위에서 처리하고, 제외 이유는 내부 coverage에 기록한다.
- 교수 발언과 보충 설명의 근거는 내부 대응표에 보존한다. 보충을 교수 발언처럼 쓰지 않는다. 귀속을 밝혀야 하는 위치에서는 짧은 문구로 구분하되, 이를 위해 별도 페이지·색상 박스를 만들지 않는다.
- 텍스트 추출·OCR의 오류를 원본 슬라이드의 오류라고 단정하지 않는다. 정정이 필요하면 실제 보이는 식·문구를 먼저 확인한다.

## 원본 교안과 설명 배치

- 슬라이드 교안은 **원본 1쪽 = 큰 절 하나**로 대응한다. `번호 있는 큰 절 제목 → 짧은 기준선 → 원본 교안 → 원본 PDF p.N 캡션 → 대응 설명` 순서를 지킨다. 교안을 요약 그림으로 대체하지 않는다.
- 큰 절은 기본적으로 새 페이지에서 시작한다. 원본 한 쪽과 해설을 묶는 안정된 배치를 사용하고, 페이지 수를 줄이려고 큰 절을 계속 이어 붙였다가 나눔을 반복 조정하지 않는다. 사용자가 분량 축약을 요청한 경우에만 1/3쪽 이하의 짧은 절을 이어 배치할 수 있다.
- 교안 이미지 폭은 `0.79\linewidth`를 출발점으로 하고 `0.79~0.88\linewidth` 안에서 가독성을 확인한다. 실제 글자가 작을 때만 확대한다. 긴 설명은 다음 쪽으로 이어 쓰며 폰트 축소로 맞추지 않는다.
- 뒤에 따로 붙인 설명은 대응하는 앞쪽 슬라이드 아래로 옮긴다. 같은 내용은 합치되 서로 다른 교수 예시·조건은 보존한다. 설명이 길면 다음 쪽으로 자연스럽게 이어 쓰고, 억지로 한 쪽에 넣느라 글자를 줄이거나 내용을 삭제하지 않는다.
- 원본 안의 제목·도형·로고는 원본의 일부이며 그대로 유지한다. 새 노트 레이어는 아래 고정 디자인을 적용한다.

## 고정 디자인

검증된 TeX 조판 설정을 재사용하되 아래 기준을 우선한다. `../scripts/deep_note_template.tex`를 쓰는 관리형 빌드도 예외가 아니다. 템플릿·글꼴 기본값이 다르다는 이유로 이 기준을 낮추지 않는다. 새 직접 제작은 이 값을 적용한 완전한 `.tex` 하나로 바로 빌드할 수 있다. 매번 다른 디자인을 만들거나 이미 맞는 간격을 미세 조정하지 않는다.

- A4, 본문 11pt, 여백 20mm, 헤더 높이 16pt, 줄간격 1.22, 첫 줄 들여쓰기 1.2em, 문단 간격 0.35em, 푸터 간격 14mm. 배경은 흰색.
- 본문은 **Noto Serif CJK KR → Noto Serif KR** 순서의 세리프체, 제목·헤더·푸터·박스 제목은 **Noto Sans CJK KR → Noto Sans KR** 순서의 산세리프체를 사용한다. 코드·파일명은 Noto Sans Mono CJK KR 또는 설치된 모노스페이스체, 수식은 LaTeX 수학 글꼴을 쓴다. 본문과 제목의 한국어 글꼴을 각각 지정한다.
- CJK 이름이 검색되지 않더라도 KR 계열 설치 이름과 실제 글꼴 파일을 확인한다. 예를 들어 Windows의 `NotoSerifKR-VF.ttf`, `NotoSansKR-VF.ttf`가 있으면 그 파일을 사용할 수 있다. Noto가 사용 가능한데 편의상 맑은 고딕을 명시해 덮어쓰지 않는다. Noto 계열이 실제로 없을 때만 설치된 한국어 세리프/산세리프 대체 글꼴을 선택하고 사용 글꼴을 QA에 짧게 남긴다. 사용자가 직접 지정한 글꼴은 우선한다.
- 표지는 과목_차시(24pt/28pt 굵게, 파랑)와 주제 한 줄. 제목 아래 폭 0.82\linewidth, 두께 0.8pt 선. 모드 홍보·제작 방식·목표 목록을 추가하지 않는다.
- 큰 제목 16pt/20pt, 소제목 12pt/15pt, 산세리프 굵게·Accent 색. 큰 절 번호는 원본 페이지와 대응하는 `1.`, `2.` 형식, 작은 절은 `2.1`, `2.2` 형식이다. 소절은 필요한 만큼만 쓰며 2~3개를 채우기 위해 설명을 늘리지 않는다.
- 핵심 결론·혼동되는 구분만 짧게 굵게 표시한다. 문단 전체를 굵게 만들지 않는다.
- `keybox`는 핵심(테두리 #1F4E79, 바탕 #EAF2F8), `warnbox`는 주의(#A64B00/#FFF4E5), `goodbox`는 기억할 점(#0B6E4F/#E9F7F1). 테두리 0.7pt, 둥근 모서리 2mm, 내부 좌우 2mm·상하 1mm, 박스 앞뒤 6pt. 페이지에 걸쳐 나눌 수 있다.
- 강조 박스는 중요한 결론·주의·검산 감각이 있을 때 사용한다. 페이지당 개수를 채우거나 줄이기 위해 내용을 반복·삭제하지 않는다. `\begin{keybox}[짧은 제목]...\end{keybox}` 형식이며 본문과 구분되는 짧은 제목을 붙인다.
- 원본 슬라이드 크기·캡션·절 시작은 앞의 ‘원본 교안과 설명 배치’를 따른다. 교안만 쪽 하단에 남고 첫 설명이 다음 쪽으로 밀리지 않게 한다.
- **목차는 생성하지 않는다.** 표지 다음 페이지부터 본문을 시작하며, 목차용 빈 페이지나 `Contents` 제목도 넣지 않는다. 참고 템플릿에 `\tableofcontents`가 있어도 호출하지 않는다. 사용자가 목차를 명시적으로 요청한 경우만 예외다.
- 본문 헤더는 왼쪽에 과목·장 이름, 오른쪽에 짧은 주제(8~16자), 산세리프 8.5~9pt로 둔다. 페이지 번호는 하단 중앙 9pt, 표지는 헤더·번호 없음, 표지 다음 본문은 1부터다.
- 비교가 실제로 필요한 경우에만 booktabs/tabularx 표를 쓴다. 자동 공식 요약·마지막 한 문장·추가 문제 부록은 생성하지 않는다.
- 템플릿 추가 패키지: `xcolor`, `titlesec`, `fancyhdr`, `tcolorbox`, `booktabs`, `tabularx`. 설치가 필요하면 제작 시간과 별도로 알리고 빌드 중 자동 설치하지 않는다.

## 교과서 수식

- LaTeX 또는 동등한 수학 조판으로 실제 교과서처럼 출력한다. `a_ij`, `x^2`, `[[1,2],[3,4]]`, `\\frac` 같은 입력 문자열을 수식 대신 그대로 인쇄하지 않는다. 프로그램 코드 자체를 가르치는 코드 인용은 예외다.
- 아래첨자·위첨자·분수·근호·벡터·행렬 괄호·행렬 성분을 수학 글꼴과 수학 레이아웃으로 조판한다. 문장 안 수식도 같은 기준을 적용한다.
- 핵심 정의·유도·대입·결과식은 `equation` 또는 `align`을 사용해 **본문과 분리된 중앙 정렬 수식**으로 배치한다. 식 번호는 오른쪽에 `(1), (2), (3)`처럼 문서 전체에서 순차적으로 붙인다. 문장 안의 짧은 기호·단위·식 참조까지 독립 수식으로 늘릴 필요는 없다.
- 여러 단계 계산은 `align` 또는 `equation` 안의 `aligned`로 등호 위치를 맞춘다. **기호식 → 수치 대입 → 결과**를 세로로 따라갈 수 있게 한다. 서로 다른 풀이 단계나 평균값·순간값을 한 줄에 가로로 묶지 않는다. 단순 병렬 정의는 짧을 때만 같은 줄에 둘 수 있다.
- 설명을 간결하게 하는 것과 수식을 압축하는 것을 구분한다. 긴 식을 작은 글씨·인라인 분수·빽빽한 한 줄로 줄이지 않는다. 필요한 중간식과 정렬은 유지하되, 자명한 등호마다 장문 설명을 추가하지 않는다.
- 수학 원고를 일반 텍스트 PDF 렌더러에 보내지 않는다. TeX 엔진·글꼴이 없으면 필요한 환경을 명확히 알리고, 깨진 수식 PDF를 완성본으로 대신 내지 않는다.

## 집필 전 확인과 시험 조판

- 집필 전에 교안 범위, 전사 위치와 해당 강의 구간, 포함·제외 내용을 기존 내부 대응표에 짧게 기록한다. 사용자가 전사가 있다고 했는데 찾지 못하면 지정 폴더를 확인한 뒤 위치를 묻는다. 이미 교안만으로 진행하라는 지시가 있는 경우를 제외하고 전사를 찾지 못한 채 완성본부터 만들지 않는다. 전사 부재와 실제 미반영 상태를 구분한다.
- 전체 분량을 집필하기 전에 실제 본문 대표 1~2쪽을 같은 템플릿으로 시험 조판한다. 해당 자료에 있는 행렬·분수·첨자·슬라이드 등 까다로운 요소로 글꼴, 수식, 이미지 크기와 설명 공간을 확인한다. 시험 원고도 기준 TeX의 일부이며 별도 비교 노트를 새로 집필하지 않는다.
- 통과한 시험 조판의 템플릿·빌드 설정·글꼴/엔진 버전·대표 입력의 해시 또는 식별값을 기존 QA 기록에 남긴다. 같은 환경·템플릿이고 새 조판 요소가 없으면 이 결과를 재사용한다. 환경·스타일 변경이나 새 수식/그림 유형이 있을 때만 관련 표본을 추가 확인한다. 재사용은 최종 PDF 전체 시각 확인을 대체하지 않는다.

## 빌드 경로

- **새 직접 제작:** 이 조판값을 적용한 완전한 TeX 문서 하나 또는 검증된 템플릿과 본문 조각 하나를 사용한다. XeLaTeX로 빌드하고, 번호·참조 확정에 필요한 재컴파일만 한다. 완전한 TeX를 본문 조각 전용 빌더에 넣지 않는다. 본문을 Markdown이나 Python 코드 안에 중복 집필하지 않는다.
- **기존 상태·관리형 실행:** `../scripts/build_study_note_pdf.py` 또는 `gongbu build <본문.tex> --note-mode deep ...`의 기존 본문 조각 계약을 유지한다. `% units: ...`와 source map·coverage·`--patched`·`verify --check-inputs` 등 기존 추적·검수 게이트를 지킨다. 상태를 없애거나 새 cycle을 만들어 실패를 우회하지 않는다.
- 문장 안의 짧은 식은 `\(...\)`, 핵심 독립 식은 `equation` / `align`을 쓴다. 교안은 PDF 페이지 직접 삽입 또는 해당 페이지의 렌더 이미지로 넣고, 자산 경로는 과목 폴더 안의 실제 위치를 쓴다.
- XeLaTeX, `fontspec`, `kotex` 또는 `xetexko`, `amsmath`, `amssymb`, `graphicx`, `geometry`와 위 조판 패키지를 사용한다. 직접 작성한 TeX만 `-no-shell-escape`로 컴파일하고, MiKTeX는 빌드 중 자동 설치를 비활성화한다. 미설치 환경은 숨기지 않고 알린다. 새 변환기·상태 시스템·전역 재설치를 노트 제작 중 추가하지 않는다.

## 완료 검수

- 최종 PDF를 열고 모든 쪽을 렌더해 순서·공백·누락·분리를 확인한다. 수식 밀집 쪽, 행렬·분수·첨자, 작은 원본 교안은 충분한 배율로 따로 확인한다.
- 글꼴 누락, 깨진 수식, 잘림·겹침, 불필요한 제목·박스·부록이 없어야 한다. 컴파일 성공과 텍스트 추출만으로 통과시키지 않는다.
- 쉬운 설명, 원자료 coverage, 주요 수식 정확성, 승인된 TeX와 PDF의 대응, 시각 QA가 끝나야 완료다. 단일 실행은 작성자 자체 점검 한 번, 명시적 다중 실행은 독립 검수 한 번이다. 더 완벽한 설명을 만들기 위한 검수를 추가하지 않는다.

## 수정 범위에 따른 재처리

- 새 직접 제작은 배치 수정에 역할 등록을 추가하지 않는다. 영향받은 페이지와 필요할 때 뒤쪽 흐름만 확인하고 통합 작업 기록을 갱신한다. 전체 내용 검수는 반복하지 않는다.
- 관리형 실행에서 템플릿의 여백·글꼴·이미지 크기만 바뀌고 기준 원고·원자료가 그대로면 `rerun --role layout_builder --change-kind output_contract`로 조판만 다시 연다. 페이지 밀림이 있으면 영향이 끝나는 뒤쪽까지 확인한다.
- 설명·수식·가정·예제·교안 선택이 바뀌면 해당 내용과 연결된 주장·coverage를 재검수한다. 관리형 실행의 국소 수정·반려·원자료 변경은 기존 `--patched`·repair·입력 갱신 게이트를 따른다.
- TeX 본문 해시까지 바뀐 수정을 스타일 변경이라는 이유로 검증에서 숨기지 않는다. 기존 상태에서 안전하게 재사용할 수 없는 경우 해당 게이트를 따르며, 검수 원장을 직접 고치거나 새 cycle을 비용 절감용 우회로 쓰지 않는다.
- 최종 전달본은 전체 쪽을 시각 확인한다. 재집필·의미 검수 범위만 줄이는 것이며 원문 coverage·수식 정확성·PDF 무결성 기준은 낮추지 않는다.
